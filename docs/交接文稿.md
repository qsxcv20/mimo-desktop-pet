## 0. 一页速览（接手先看这段）

一个**住在 MiMo 应用窗口内部**的 MiMo 角色桌宠（橙白黑三色、双马尾、女巫帽的兔耳少女），带：

- 气泡显示 MiMo 状态 + 小米额度 / 用量
- 隐藏彩蛋：点满 30 次解锁，**双击**桌宠弹出 9 张表情包贴纸
- 自动贴边、空闲溜达、跟随 MiMo 任务状态变脸

**当前状态：功能全部可用，实机测试全绿。** 最近一轮修掉了 6 个真 bug（见 §6），不要回退。

**最重要的一句话**：桌宠是 **Win32 owned window** 挂在 MiMo 主窗口上，**不是** `SetParent` 子窗口，也不是独立桌面浮窗。所有位置坐标都是 **MiMo 客户区坐标**。改任何涉及位置 / owner 的代码前，先读 `docs/MiMo-Mate-桌宠制作流程.md` §4。

## 3. 怎么跑起来

### 3.1 启动方式：MiMo 联动（2026-11-09 定案）

**用户要求**：不要桌面快捷方式，只要 **MiMo 开启就联动唤醒桌宠、MiMo 关闭就关闭桌宠**。

**实现**：一个静默常驻的 watcher + 桌宠侧的联动退出。

```text
注册表 Run（登录自启，静默 pythonw，无控制台窗口）
     │
     └─→ tools\launch_mimo_pet.py --watch      ← 常驻 watcher
              ├─ MiMo 在跑 且 桌宠没跑 → 拉起桌宠
              └─ MiMo 不在 → 什么都不做（桌宠自己会退）
                          │
                          ▼
                 pet\mimo_pet.py  桌宠
                   ├─ attach_host() 找到 MiMo 窗口 → 挂上去显示
                   └─ 找不到 MiMo 持续 exit_grace 秒 → 退出进程
```

| 配置项 | 默认 | 含义 |
|---|---|---|
| `link_mimo` | `true` | 联动开关：MiMo 关 → 桌宠退 |
| `exit_grace` | `8.0` | 找不到 MiMo 多少秒后退出（给 MiMo 冷启动留宽限）|
| `launch_mimo` | `false` | 桌宠**不再**主动把 MiMo 带起来 |

**实测（2026-11-09）**：

| 场景 | 结果 |
|---|---|
| MiMo 在跑 → 启动 watcher | 桌宠约 12 秒内自动出现，事件连接正常 |
| 关掉 MiMo | 4 秒时桌宠还在（宽限期内），18 秒后进程已退出 |
| 重开 MiMo | 桌宠自动回来，事件连接正常 |

**为什么不用计划任务**：每分钟执行 `guard_task.cmd` 会让 cmd.exe 闪一个黑框
（用户明确要求去掉）。注册表 Run 项用 `pythonw.exe`，**全程无任何控制台窗口**。

**用户右键「退出」桌宠**时写 `pet\pet_disabled` 标记 —— watcher 尊重它，不会擅自拉回来；
联动退出（MiMo 关）**不写**这个标记，所以 MiMo 再开时桌宠会回来。

```powershell
# 手动启动 watcher（等价于登录自启）
pythonw.exe tools\launch_mimo_pet.py --watch
```

## 5. 架构要点（改代码前必读）

### 5.1 承载方式：Win32 owned window

- **不用 `SetParent`** —— 已被实测证伪（MiMo 是 D3D 渲染，`SetParent` 后桌宠完全不显示）
- 做法：`SetWindowLongPtrW(hwnd, GWLP_HWNDPARENT, mimo_hwnd)` 把桌宠设成 MiMo 的 **owned window**
- 效果：桌宠随 MiMo 一起最小化 / 恢复 / 移动 / 缩放，永远在 MiMo 之上，且**只能待在 MiMo 窗口内**
- ⚠️ **Qt 的 `show()` 会清掉 `GWLP_HWNDPARENT`** —— owner 必须在 `show()` 之后**幂等补设**（`_apply_owner()`：读实际指针，缺了就补）

### 5.2 坐标语义

- `pet_config.json` 的 `x` / `y` 是 **MiMo 客户区坐标**（`layout_version: 2`）
- 语义变更会自动重置位置（v1 是桌面浮窗的屏幕坐标）
- 换算：`H.client_to_screen(host_hwnd, 0, 0)` 拿到客户区屏幕原点

### 5.3 事件链路

```
MiMo 本地 API（127.0.0.1，token 在 %APPDATA%\Xiaomi MiMo\desktop-api.json）
  GET /v1/health
  GET /v1/sessions?limit=20          ← 取 time.updated 最大的会话
  GET /v1/sessions/<id>/events       ← SSE 事件流
        ↓
mimo_link.py → PetBrain → 表情映射
        ↓
mimo_pet.py._apply_state() → 切表情 + 弹气泡
```

事件 → 表情：

| 事件 | 表情 |
|---|---|
| `busy` / `text-partial` | think |
| `busy` 之后的 `idle` / `ui(kind=usage)` | happy（约 2.6 秒后回落） |
| `ui(kind=error)` / `permission*` / busy > 150 秒 | tired |

### 5.4 额度取数（三级兜底）

1. **CDP** —— 调 MiMo 自己的 `window.mimo.getUserUsage()`（需要 MiMo 带 `--remote-debugging-port=9333` 启动）
2. **开放平台签名 API** —— `https://platform.xiaomimimo.com/api/v1/tokenPlan/usage` 等，走小米 SSO 换票链
3. **本地 SSE + 缓存**

凭据来自 MiMo 的 Chromium cookie 分区（`Partitions\xiaomi-account` → `rp-browser` → 默认 `Network\Cookies`，DPAPI + AES-GCM 解密）。**MiMo 运行时 cookie 库被排他锁**（WinError 32），复制会抛异常并被吞掉。

> ⚠ **抓凭据是手工操作，不是自动的**：真正执行抓取的是 `tools\capture_creds.py`（要**先完全退出 MiMo**再跑），**没有接进 launcher / watchdog**。`mimo_quota.refresh_credential()` 全工程无人调用 = 死代码。
> 另：CDP 成功时平台层的错误会被丢弃（`perr` 不写进 snapshot），所以 `pet_status.json` 里只看得到 `balance:null`，**复验不了 70016**。

## 6. 已踩过的坑（**最重要的部分**，别重蹈覆辙）

### 6.1 承载 / 位置

| 坑 | 表现 | 正确做法 |
|---|---|---|
| `SetParent` 做子窗口 | 桌宠完全不显示（MiMo 是 D3D） | 用 owned window |
| Qt `show()` 清 owner | 桌宠飘到桌面顶层 | `_apply_owner()` 幂等补设 |
| 宿主最小化 / 收托盘 | `ClientToScreen` 返回 (-32000,-32000) 哨兵，桌宠被一起挪出屏幕 | `_sync_position()` 里先判断 `IsIconic` / `IsWindowVisible`，是就 `hide()` |
| MiMo 最小化再恢复 | **Chromium 渲染层黑屏** | `python tools\restart_mimo.py --port 9333`；桌宠会自动重绑新窗口 |
| MiMo 重启换端口 token | SSE 重连打在一个没人听的端口上，等 10 秒超时 | 重连时主动 `client.refresh_creds()`（12 秒 → 4.1 秒） |

### 6.2 位置逻辑（2026-11-09 修）

| 坑 | 表现 | 修法 |
|---|---|---|
| **桌宠先于 MiMo 启动** | 客户区尺寸是 0 → 坐标退化成 (0,0) → **桌宠永久钉在 MiMo 左上角** | 位置算不出来时标 `_pos_deferred`，`attach_host()` 挂上宿主后按记忆的角落重新贴位 |
| **退出时写回退化坐标** | `quit()` → `_save_pos()` 把 (0,0) 写进配置，**用户记住的位置被冲掉** | `_save_pos()` 在 `_pos_deferred` 期间**不落盘** |
| **边标签认不出** | `snap_position()` 产出 `l/r/t/b` 存进 `cfg["corner"]`，但 `corner_pos()` 只认四角 → `table.get(corner, table["br"])` 静默吞成右下角，**重启后跳位** | `corner_pos()` 补上四种边的还原逻辑 |
| **改配置前没停桌宠** | 桌宠退出时把内存旧配置写回 | **任何改配置前先 `pet_control.py stop`** |

### 6.3 鼠标 / 交互

| 坑 | 表现 | 修法 |
|---|---|---|
| **自己按时间窗数 release 判多击** | 连点被误判成多击，`on_multi_click` 的 count 一路涨到 9，**用户根本点不出「单击」** | 计数（彩蛋）与手势语义**必须解耦**：`on_tap()` 在事件层按物理点击计，`_resolve_gesture()` 在结算层判手势 |
| **`drag_to()` 写在位移阈值外面** | 按住鼠标时 1 像素抖动就把桌宠拽走；点击前 `SetCursorPos` 产生的 `WM_MOUSEMOVE` 可能在下压之后才送达 → **连点解锁时桌宠乱跑、后续点击全打空** | `if self.moved or 距离 > 6:` 才 `drag_to()` |
| **dblclick 事件不可靠** | 实测这个环境下 `WM_LBUTTONDBLCLK` **根本不合成**（连最小复现窗口都收不到），老版本「双击出贴纸」其实从未真正生效 | 判定改成**只数 release**（1=单击 2=双击 3=三击）；dblclick 到达时计 1 次并用 `_suppress_release` 抑制紧随的 release；等待窗口 500ms = 系统 `GetDoubleClickTime()` |
| 贴纸模式下单击 | 直接弹额度卡片会把刚看到的贴纸立刻盖掉 | 新规则：贴纸亮着时单击**切回额度气泡**（查看用量）—— `on_single_click` 里判断 `_bubble_mode == "sticker"` 就走 `show_bubble()` |

### 6.4 气泡

| 坑 | 表现 | 修法 |
|---|---|---|
| 尾巴被主体盖住 | 看不见指向桌宠的小尖角 | 气泡主体要留出尾巴位置的空白 |
| **气泡抢气泡** | MiMo 发来 `happy` → `_apply_state()` → `show_bubble()` → 刚弹的贴纸被额度卡片盖掉 | 三处都要加 `_bubble_mode != "sticker"` 守卫：`_refresh_bubble_content()` / `_apply_state()` / `shot_mimo.py`（后者加 `--keep`） |
| 气泡半透明 | `PrintWindow` 抓到的像素被 MiMo 深色背景污染（额度气泡非白占比也有 94.8%） | **验收看状态**：`pet_status.json` 的 `egg.sticker_mode`（100% 可靠）；窗口尺寸只作兜底（贴纸固定 228×270，额度当前 301×172），不看颜色 |

### 6.7 脚本 / 环境（这些坑很费时间）

| 坑 | 说明 |
|---|---|
| **控制台是 GBK** | 所有 Python 脚本开头加 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` —— ⚠ **必须包 try/except**，原因见下面两行 |
| **pythonw 下 `sys.stdout` 是 `None`** | 桌面快捷方式点了完全没动静，日志里什么都没有 | `pyw.exe` / ShellExecute 是 GUI 子系统、不分配控制台 → `sys.stdout` 是 `None`，脚本第一行 `sys.stdout.reconfigure()` 直接 AttributeError 秒死。**所有脚本的 reconfigure 都要包 try/except**（2026-11-09 批量修了 65 个文件）。`print()` 本身在 stdout 为 None 时会静默丢弃，所以只有这一行致命 |
| **桌面被重定向** | 快捷方式建好了，但用户在桌面上根本找不到 | 不能拼 `USERPROFILE\Desktop`，要用 `SHGetFolderPathW(CSIDL_DESKTOPDIRECTORY)` 拿真实桌面（本机实际在 `Documents\kimi\Workspaces\桌面`）|
| **PowerShell here-string / `python -c` 内联** | 引号极易被破坏 → **一律写 `.py` 文件再执行** |
| **ripgrep 会把 MiMo 的大体积 bundle 当二进制跳过** | 搜 bundle 必须用自写 Python 脚本 |
| **cmd.exe 按 GBK 读 `.cmd`** | `guard_task.cmd` / 开机自启脚本必须**用 GBK 写盘**（`setup_launcher.py` 已处理） |
| **删除文件** | 必须用受信任启动器：`& "C:\Users\yang2\.minimax\bin\mavis-trash.cmd" <paths>`（裸 `mavis-trash` / `rm --` / `Remove-Item` 会被安全策略拦） |
| **写入 JSON 的 args 文件** | 必须无 BOM |
| `ctypes` 脚本 | `from ctypes import wintypes as wt` 要放**模块顶层**，否则函数内 `wt` 变局部变量报 NameError |
| Pillow | `im.width()` 是**属性**不是方法（`im.size` 同理），写成 `im.width()` 报 `TypeError: 'int' object is not callable` |
| 状态文件刷新 | 每秒才刷一次，实机测试读计数要留容差 |
